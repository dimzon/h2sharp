# TestIndexHints: сеттер CommandText не должен бросать при открытом читателе

## Диагноз (по вашему замечанию — верному)

`TestQuotedIdentifier` присваивает `stat.CommandText` **внутри** `using` с открытым читателем, а выполняет второй запрос уже **после** его закрытия — выполнение на открытом читателе тест не делает. Порт бросает `InvalidOperationException` прямо в сеттере `H2Command.CommandText` — проверка стоит не там:

- В ADO.NET (SqlClient) присвоение `CommandText` при открытом читателе легально; конфликт («There is already an open DataReader…») возникает при **выполнении**.
- В порту проверка выполнения уже есть и на своём месте: `ExecuteDbDataReader` бросает «The command already has an open reader» при `openReaders > 0`.
- JDBC-эталон идёт дальше: неявно закрывает предыдущий результат при следующем выполнении того же Statement.

## Правка

`src/H2Sharp/Data/H2Command.cs` — снять бросок из сеттера `CommandText` (оставить присвоение с комментарием о разделении ответственности: сеттер легален, конфликт ловится при выполнении). Проверки в `ExecuteDbDataReader` и в сеттере `DbConnection` не трогаю.
