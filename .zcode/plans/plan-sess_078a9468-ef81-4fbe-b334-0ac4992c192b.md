## Контекст

Реализуем P0 + P1 из `docs/ANALYSIS_SYSTEM_DATA_COMMON.md` (batch-фабрика, `IDbColumnSchemaGenerator`, события `H2DataAdapter`, порт `DatabaseMetaLocal`, `GetSchema` с эталонными колонками). Работа — в отдельном бранче и отдельной папке. В `main` параллельно работает другой агент, поэтому в конце делаем **полноценное двустороннее слияние** с разрешением конфликтов, а не fast-forward и не stash чужих правок.

## Git-процесс

1. Немедленно, до чтения/правки кода:
   `git worktree add C:\Work\h2sharp-system-data-common -b feature/system-data-common`
2. Скопировать туда `docs/ANALYSIS_SYSTEM_DATA_COMMON.md` только как справку; в коммиты не включать (в `main` он untracked, коммит создал бы коллизию). Коммитить только явные пути, никогда `git add -A`.
3. Вся работа, сборка и тесты — в `C:\Work\h2sharp-system-data-common`.
4. Интеграция с активным `main`:
   - перед финалом в worktree: `git merge main --no-ff -m "Merge main into feature/system-data-common"`;
   - разрешить конфликты (ожидаемые точки: `src/H2Sharp/Tables/TableTypes.cs`, `Data/H2Connection.cs`, docs), сохраняя и правки main, и наши;
   - прогнать полный набор тестов уже на объединённом коде;
   - если `main` сдвинулся после этого — повторить merge main → feature.
5. Финальное слияние: в основной папке `git switch main` и `git merge --no-ff feature/system-data-common`. **Ничего не stash’ить и не откатывать**: если рабочее дерево `main` грязное в затрагиваемых файлах, остановиться и сообщить пользователю — другой агент мог не закоммитить работу.
6. После merge: `git worktree remove C:\Work\h2sharp-system-data-common`; бранч оставить; **push не делать** без отдельной просьбы.

## Этапы реализации (в бранче)

**1. Batch-фабрика (малый).** `H2Batch`: `internal H2Batch(H2Connection? connection = null)`. `H2ProviderFactory`: `CreateBatch() => new H2Batch()`, `CanCreateBatch => true`. Тест: фабричный batch + `batch.Connection = connection` + выполнение; `connection.CreateBatch()` не ломается.

**2. `IDbColumnSchemaGenerator` (малый).** `H2DataReader` реализует интерфейс (explicit `GetColumnSchema()`), общий приватный `ColumnSchema()` для sync/async, обновить устаревший комментарий. Тесты: sync == async, пустая схема без колонок; прогон `AdoNet.Specification.Tests`.

**3. События `H2DataAdapter` (средний).** Новые `H2RowUpdatingEventArgs`/`H2RowUpdatedEventArgs` с типизированным `H2Command? Command`; в `H2DataAdapter` — события `RowUpdating`/`RowUpdated` и overrides `CreateRowUpdatingEvent`/`CreateRowUpdatedEvent`/`OnRowUpdating`/`OnRowUpdated`. `FillError` уже поднимается `DataAdapter.Fill` — только тест. Тесты с ручными командами: порядок событий, типизированные args, `SkipCurrentRow`, `FillError.Continue`. `H2CommandBuilder.SetRowUpdatingHandler` остаётся пустым.

**4. Порт `DatabaseMetaLocal` (крупный).** Новые `src/H2Sharp/Jdbc/Meta/DatabaseMeta.cs`, `DatabaseMetaLocalBase.cs`, `DatabaseMetaLocal.cs` (namespace `H2Sharp.Jdbc.Meta`) — 1:1 из `org.h2.jdbc.meta`; `DatabaseMetaLocalBase` public из-за требования C# к доступности базового класса (записать в коде и `MIGRATION_STATUS.md`). Реализовать Tables/Columns/Schemas/Catalogs/TableTypes/IndexInfo/PrimaryKeys/Imported-Exported-CrossReference/TypeInfo/SQLKeywords/PseudoColumns/BestRowIdentifier/SearchStringEscape/DefaultNullOrdering/версии; пустые коллекции из base. Явные `TODOException` с именем недостающего для `GetProcedures`/`GetProcedureColumns` (`FunctionAlias`), `GetColumnPrivileges`/`GetTablePrivileges` (`Right`/`User`, D-004), `Get*Functions` (`Help`); в `GetSchema` они не выставляются. Добавить эталонные `Table.GetSQLTableType()` и `Column.GetDefaultSQL()` и использовать их. `Session.GetDatabaseMeta()` вернуть `DatabaseMeta` вместо `object`; `SessionLocal` → `new DatabaseMetaLocal(this)`. Оракулы `tests/H2Sharp.Tests/MetadataOracleTests.cs` (`JavaOracleFact`) по Tables/Columns/Schemas/Catalogs/TableTypes/IndexInfo/Keys/TypeInfo/SQLKeywords; `DATA_TYPE` не сравнивать (`SqlDbType` vs `java.sql.Types`), `PAGES` — только если расхождение объяснено хранилищем, с записью в тесте.

**5. `GetSchema` (крупный).** `H2Connection`: три sync- и три async-перегрузки (отмена через `Task.FromCanceled`, иначе sync); закрытое соединение → `InvalidOperationException`, неизвестная коллекция/лишние restrictions → `ArgumentException`. Коллекции: `MetaDataCollections`, `Restrictions` (стандартная ADO.NET-форма), `DataTypes` → `GetTypeInfo`, `ReservedWords` → `GetSQLKeywords` (split, колонка `ReservedWord`), `Tables`, `Columns`, `Indexes` (table обязателен, пост-фильтр по INDEX_NAME), `ForeignKeys` (→ imported keys, table обязателен), `TableTypes`, `Catalogs`, `Schemas`. Значения — через `H2ValueMapper.ToObject`; типы колонок — из `GetColumnType`. Тесты `H2GetSchemaTests`: каждая коллекция, фильтры, ошибки, async/отмена, закрытое соединение. Заодно исправить устаревший header `H2Connection.cs`.

## Проверка (в worktree, затем повторно после merge main → feature)

2. `dotnet test tests/H2Sharp.Data.Tests`.
3. `dotnet test tests/H2Sharp.Tests --filter "FullyQualifiedName~MetadataOracleTests"` (при наличии jar/java; `H2SHARP_REQUIRE_ORACLE=1`).
4. `dotnet test H2Sharp.sln --filter "Category!=BlockedByPort"`.

Затем — полное слияние с `main` по процессу выше.
