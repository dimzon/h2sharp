## Пользовательские агрегаты: план «инфраструктура → примеры → перенос»

### Контекст
MSSQL CLR-агрегаты и H2-эталон показывают общий паттерн; в порте пользовательских агрегатов нет (карта точек расширения собрана: `AbstractAggregate`, `SelectGroups`, `Parser.ReadFunction`, `ExtensionConfiguration/ExtensionRuntime`). Требования: сначала инфраструктура, потом примеры (string_agg + нестандартное), и лишь затем аккуратный перенос встроенных; дизайн интерфейсов — с учётом производительности (без лишнего боксинга/аллокаций).

---

### Фаза 1. Инфраструктура (полностью)
**Публичный контракт — `src/H2Sharp/Data/Extensions/` (namespace `H2Sharp.Data.Extensions`):**
```csharp
public readonly record struct AggregateInput(
    IReadOnlyList<object?> Values,   // CLR-значения аргументов; буфер движка, не хранить после Add
    int RowIndex);

public interface IH2Aggregate
{
    TypeInfo GetResultType(IReadOnlyList<TypeInfo> inputTypes);
    void Init();
    void Add(AggregateInput input);
    object? GetResult();
    void Merge(IH2Aggregate other) { }
}
public interface IH2OrderedAggregate : IH2Aggregate { void SetOrderBy(SortOrder order); }
public sealed class AggregateOptions { /* Deterministic, IgnoreNulls, InvariantToDuplicates, InvariantToOrder, ResultType? */ }
```
Базовые классы (в `H2Sharp.Data.Extensions`): `AggregateBase`, `SimpleAggregateBase`, `OrderedAggregateBase`, `CollectingAggregateBase`.

**Производительность в дизайне:**
- буфер значений переиспользуется движком (один массив на строку; контракт запрещает хранение ссылки после `Add`);
- `RowIndex` — value-тип, без боксинга; `GetResultType` кэшируется (вызывается один раз);
- базовые классы держат состояние в полях (без лишних обёрток); `CollectingAggregateBase` хранит список входов (или, для options-ядра, список `Value`/`object` без record-обёртки);
- при ordered: компаратор/сортировка настраиваются один раз через `SetOrderBy`, без создания делегатов на каждый вызов;
- анти-паттерны документируются (избегать конкатенаций строк в цикле, List<object> в горячем пути и т.п.).

**Регистрация/исполнение:**
- `IH2Extensions.RegisterAggregate<T>(name, Func<IH2Aggregate> factory, AggregateOptions options)` + `RegisterRawAggregate` (`H2Sharp.Data`);
- `AggregateDefinition` в `ExtensionConfiguration`, снапшот в `ExtensionRuntime` (`HasAggregate/FindAggregate`);
- `ClrAggregate : AbstractAggregate` (internal, `Expressions/Aggregate/UserDefined/`): фабрика → `AggregateInput` → `GetResult` → ToValue; DISTINCT/FILTER/OVER наследуются; ordered пробрасывает `orderBySort`;
- `Parser.ReadFunction` — ветка после built-in агрегатов.

**Инфраструктурные тесты**: регистрация/видимость/закрытость соединения; smoke ручной реализации интерфейса; базовые классы (Simple/Ordered/Collecting) на тривиальных примерах.

### Фаза 2. Примеры на новой инфраструктуре
1. **string_agg**: `Concat : OrderedAggregateBase` — `SELECT CUSTOM_STRAGG(VAL, ',') FROM T GROUP BY GRP`; варианты DISTINCT/FILTER/NULL/пустая группа.
2. **Нестандартное**: `GeometricMean : SimpleAggregateBase` (произведение/счётчик; результат извлекается как decimal) — пример агрегата, которого нет среди встроенных; плюс проверка использования `CollectingAggregateBase` через `Median`-подобный пользовательский агрегат для полноты покрытия категорий.
Тесты: `tests/H2Sharp.Data.Tests/H2AggregateTests.cs`.

### Фаза 3. Аккуратный перенос существующих встроенных
- Только после зелёных фаз 1-2; строго по одному агрегату с сохранением всех специализаций (типы через `GetSumType/GetAvgType`, DISTINCT, OVER, QuickAggregateQuery, список `Aggregates`).
- Очередность: простые (SUM/MIN/MAX/COUNT/EVERY/ANY_VALUE/BIT*/BOOL_*) → AVG/STDDEV/VAR (математика в подклассах) → MEDIAN/LISTAGG-стиль — только если фаза 2 покажет уверенность; JSON/ENVELOPE/RANK-семейство остаются встроенными (семантика окон/форматов).
- Критерий приёмки: бинарная эквивалентность со старыми путями (существующие Specs/Data-тесты по агрегатам остаются зелёными + оракул-тесты без изменений).
