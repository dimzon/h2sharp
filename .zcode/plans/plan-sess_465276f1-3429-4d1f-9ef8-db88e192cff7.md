## Контекст

Запрос: проанализировать пространство имён `System.Data.Common` (.NET 10) и определить, какие интерфейсы, классы и события провайдер H2Sharp может ещё унаследовать/реализовать. Пользователь выбрал формат: **документ + план внедрения**.

Уже собраны и подтверждены факты (два Explore-агента + сверка с learn.microsoft.com):
- Провайдер в `src/H2Sharp/Data/` уже реализует практически весь базовый набор: `DbConnection`, `DbCommand`, `DbDataReader`, `DbParameter`/`DbParameterCollection`, `DbTransaction`, `DbProviderFactory`, `DbConnectionStringBuilder`, `DbDataAdapter`, `DbCommandBuilder`, `DbException`, а также современные `DbDataSource`, `DbBatch`/`DbBatchCommand`/`DbBatchCommandCollection`, `DbColumn`.
- Не реализовано: `IDbColumnSchemaGenerator`, `GetSchema`/`GetSchemaAsync`, живое поведение `DbDataAdapter` (события `RowUpdating`/`RowUpdated`/`FillError` не поднимаются, `H2CommandBuilder` — заглушка с NotSupported), `DbEnumerator`.
- Найденные дефекты: `H2ProviderFactory.CanCreateBatch = false` при рабочем `DbBatch`; `StateChange` поднимается только в синхронных `Open`/`Close`, не в async-путях; `H2SharpException.SqlState` нужно проверить на переопределение `DbException.SqlState`.
- Документация опровергла: `StatementCompleted` — событие не базового `DbCommand` (провайдерское, как у SqlClient); `IDbConnectionExtension`/`IDbTransactionExtension`/`IDbDataSource` в BCL .NET 10 не существуют (404 в обоих пространствах имён).

## Задача

Создать один документ `docs/ANALYSIS_SYSTEM_DATA_COMMON.md`, который содержит:

1. **Резюме** — что уже есть и что стоит добавить, в двух абзацах.
2. **Статус-кво** — таблица из 13 реализованных типов с указанием файлов и перекрытых членов.
3. **Кандидаты «наследовать/реализовать»** с приоритетами:
   - **P0 — дефекты** (правки в существующей архитектуре): `CanCreateBatch` → true + override `CreateBatch`; `StateChange` в `OpenAsync`/`CloseAsync`; проверка/исправление `SqlState` как override.
   - **P1 — функциональные дополнения**: `IDbColumnSchemaGenerator` на `H2DataReader` (sync `GetColumnSchema` поверх существующего билдера схемы); `GetSchema`/`GetSchemaAsync` на `H2Connection` по образцу `JdbcDatabaseMetaData` из эталона (коллекции MetaDataCollections, DataTypes, ReservedWords, Tables, Columns, Indexes, ForeignKeys, Procedures); завершение `H2DataAdapter` (`H2RowUpdatingEventArgs`/`H2RowUpdatedEventArgs`, `CreateRowUpdatingEvent`/`CreateRowUpdatedEvent`/`OnRowUpdating`/`OnRowUpdated`/`OnFillError`, публичные события `RowUpdating`/`RowUpdated`/`FillError`); `DbEnumerator`.
   - **P2 — опционально**: `H2CommandBuilder` (`QuoteIdentifier`/`UnquoteIdentifier` + генерация команд одной таблицы — разблокирует авто-генерацию адаптера); async-перегрузки `DbTransaction` (`CommitAsync`/`RollbackAsync`/`SaveAsync`/`ReleaseAsync`); `VisibleFieldCount`; провайдер-специфичное свойство параметра с `[DbProviderSpecificTypeProperty]`; кастомное событие `StatementCompleted` на `H2Command` (по образцу SqlClient).
   - **Не делать** (с обоснованием): `IDbConnectionExtension`/`IDbTransactionExtension`/`IDbDataSource` (нет в BCL), `DbDataSourceEnumerator` (нет серверного обнаружения), `DBDataPermission` (устаревшая CAS), EF6 `DbProviderServices`/`DbCommandDefinition` (не нужны EF Core), `IExtendedDataRecord`/`DataRecordInfo` (EF-специфика), `IColumnMapping`/`ITableMapping` (внутренние для адаптера).
4. **Сводная таблица событий** — что поднимается, что наследуется, что добавить, на каких классах и с какими делегатами.
5. **Карта на эталон H2** — какие пункты имеют Java-аналог (`GetSchema` ← `JdbcDatabaseMetaData`, `DbException` ← `SQLException`, StateChange ← autoCommit/close-события) и какие являются чистым .NET-слоем без аналога (адаптер/билдер/enumerator) — с пометкой, что последние требуют осознанного решения в духе ADR-001 (в репозитории действует правило «не изобретать сверх эталона»; эти пункты — расширение .NET-границы, а не SQL-семантики).
6. **План внедрения** — упорядоченные шаги для будущих PR:
   - Шаг 1: P0-дефекты (правки + юнит-тесты).
   - Шаг 2: `IDbColumnSchemaGenerator` + `DbEnumerator` (малые, независимые).
   - Шаг 3: `GetSchema`/`GetSchemaAsync` (+ оракульные тесты против `JdbcDatabaseMetaData` по протоколу `REGRESSION_TEST_PROTOCOL.md`).
   - Шаг 4: `H2DataAdapter` с событиями (+ тесты).
   - Шаг 5 (опц.): `H2CommandBuilder` генерация.
   - Для каждого шага: затрагиваемые файлы, тип тестов, фильтр прогона.

## Ограничения

- В рамках этой задачи **только документ** — код не меняется, никакие файлы src/tests не редактируются.
- Документ пишется на русском, в стиле существующих `docs/` (ADR, SPRINT) с таблицами-файлами-строками.
- Факты в документе — только из подтверждённых источников (отчёты агентов, learn.microsoft.com, код репозитория); каждый кандидат снабжается ссылкой на конкретный файл провайдера.

## Проверка

- Документ создаётся в `docs/`; структура и таблицы проверяются прочтением.
- Никакие тесты не затрагиваются (код не меняется).
- Шаги плана внедрения верифицируемы по отдельности: `dotnet test tests/H2Sharp.Data.Tests --filter ...` + расширение набора `AdoNet.Specification.Tests` после реализации.
