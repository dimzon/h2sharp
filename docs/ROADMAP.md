# H2Sharp roadmap

Status legend: **done** / **in progress** / **todo**

## Phase 0 — Bootstrap — done

* Repository, solution skeleton, `Directory.Build.props` (net8.0 + net10.0,
  nullable, warnings-as-errors), central package management.
* Reference H2 checkout pinned in `reference/H2_COMMIT.txt` (H2 2.5.259-SNAPSHOT).
* `docs/PORTING.md` — porting contract, type mapping, name-collision resolutions.
* `NOTICE.md`, `LICENSE-H2.txt` — MPL-2.0 OR EPL-1.0, file-level copyleft.
* CI: build + test on Windows and Linux, plus a differential conformance job.
* Cross-language oracle harness (`tests/H2Sharp.Tests/Oracle/JavaOracle.cs`) that
  compiles and runs snippets against the reference JVM and H2 jar.

## Phase 2 — MVStore — done

`store/*`, `compress/*`, `mvstore/*` including `mvstore/tx`, `mvstore/type`,
`mvstore/rtree`, `MVStoreTool`. Highest-risk phase: the file format must stay
byte-compatible.
Gate (closed): a database file written by H2Sharp opens in the reference H2 and vice
versa — `tests/H2Sharp.Tests/MvStoreFileCompatTests.cs` dumps plain maps both ways
(ints with removals, unicode strings, a 100 KB value, boundary longs) and diffs them.
Deliberate skips (see MIGRATION_STATUS.md): `OffHeapStore`/`AppendOnlyMultiFileStore`/
`MFChunk` (dead backends, zero references), `MVStoreTool.main` (CLI), encryption
(`FileEncrypt`; `TestEncryptedFile`/`TestNewerWriteVersion` stay private until deletion),
`TestTransactionStore.testCompareWithPostgreSQL` (needs live PostgreSQL), `SpatialKey`
(engine `Value` subclass; tests use `DefaultSpatial`).
Not in this phase after all: `mvstore/db/*` (MVTable, indexes, Store, ValueDataType) —
it needs `Value` (done) *and* `Session` (phase 6), so it moves with the table engine.

## Phase 3 — Values and schema — next

`value/*` remainder (`Transfer`, `lob/*`, `CharsetCollator`, `CompareModeIcu4J`),
`schema/*`, `table/*`, `index/*`, `mvstore/db/*`. Order is dependency-driven:
**next up is step 2**, the session-free core of `table/`.

1. `value/` remainder — **done for what is portable**: `CharsetCollator` and the
   `CHARSET_` branch of `CompareModeDefault` (the only collation whose weights are
   the platform's own bytes, so it is exact; see MIGRATION_STATUS.md). Left, and
   why: `DEFAULT_`/`ICU4J_` collations need `java.text.Collator` weights, measured
   and not reproducible; `Transfer` needs `Session` and `DataHandler`; `lob/*`
   needs `DataHandler`; `ValueToObjectConverter`/`2` need the JDBC types, which
   arrive with the provider.
2. `table/` session-free core: `Column`, `IndexColumn`, `ColumnResolver` and friends.
3. `index/` session-free core: `IndexType`, `IndexSort`, remaining cursors.
4. `mvstore/db/*` against the above (`ValueDataType`, then `MVTable` + indexes).
   `MVTable`/`Store` need `Session`, which arrives as the minimal surface phase 6
   can provide early (the same trick as `ResultInterface` needing one `Session`
   method, not twenty).
5. `schema/*` last — it needs `Database`.

Gate: `TestMVTableEngine` (the reference's 57 KB table-engine suite) ported and green;
it exercises tables, primary/secondary/spatial indexes, and LOB storage together.

## Verified behaviour so far

Facts established against the reference JVM rather than assumed:

* `Bits.uuidToBytes` writes the canonical UUID **text** byte order; see
  `docs/notes/uuid-byte-order.md`. `Guid.ToByteArray()` must not be used.
* `MathUtils.nextPowerOf2` rejects `x > 0x40000000`, not just negatives.
* `Utils.sortTopN` places the n **smallest** values (per comparer) in
  `[from, to)`, ascending — despite its javadoc saying "descending order".
  Elements outside that range are unspecified and differ run to run in both
  implementations because the pivot is random.
* `Integer.decode` semantics for property parsing: `0x`/`#` prefixes are hex, a
  leading `0` is octal, and surrounding whitespace is rejected.
* H2 error codes do not always equal the plain SQLSTATE number:
  `NULL_NOT_ALLOWED` is 23502 (not 90022) and `DUPLICATE_KEY_1` is 23505 (not
  42501). The `ErrorCode` table is verified constant-by-constant against the
  reference JVM via reflection, so do not hand-edit `Api/ErrorCode.cs` — rerun
  `python tools/port_errorcode.py` instead.
* `StringUtils.appendHex(builder, x, 2)` emits **four** hex digits, not two: the
  `bytes` argument really counts bits/8 but the loop runs `bytes * 8 / 4` times.
  So a tab is escaped as `\0009`.
* `DbException.quote` escapes anything whose `Character.getType` ordinal is 0
  (UNASSIGNED) or in 12..18 (SPACE_SEPARATOR..SURROGATE), except a plain space.
  Letters, digits, punctuation and symbols are kept literal — an emoji stays
  literal, and a Private Use character becomes `\e000` (the `\+xxx` form is only
  for astral code points above the BMP).
* `java.text.MessageFormat` rules, verified exhaustively against the JVM; see
  `docs/notes/message-format.md`. Notably `a'b` renders as `ab` (a lone
  apostrophe vanishes), which shows up in H2's own message 90146.
* The message catalogue is chosen from `Locale.getDefault()` in Java and from
  `CurrentUICulture` in .NET; a translation is *prepended* to the English text
  rather than replacing it.
* Java applies the Unicode **full** case mapping, .NET the **simple** one, so
  `"ß".ToUpperInvariant()` is `"ß"` where Java gives `"SS"`, `İ` lowercases to
  `i` + U+0307 rather than `ı`, and `ı` uppercases to `I` where .NET leaves it
  alone. `Util/CaseFolding.cs` is generated from the reference JVM and holds the
  390 uppercase and 288 lowercase overrides.
* `java.net.URLEncoder` emits **uppercase** percent-escapes and replaces an
  unpaired surrogate with `?`, where .NET's default UTF-8 encoder emits U+FFFD.
* `StringUtils.startsWithIgnoringCase` is `Collator.getInstance()` at PRIMARY strength
  compared over `text.substring(0, prefix.length())`, so it is **locale-dependent by
  construction**. PRIMARY is not "ignore case": CLDR root gives different primary
  weights to a Cyrillic case pair (`а`/`А`) and to a fullwidth pair (`Ａ`/`ａ`), while
  `ru-RU` tailors the Cyrillic pair to be equal. The port follows `CurrentCulture` with
  `IgnoreCase | IgnoreNonSpace`; the residual difference is pinned by a test instead of
  hidden. Both `ru-RU` and `en-US` are run against the JVM.
  Bringing in ICU does **not** close the gap: `CompareInfo.Compare` and
  `CompareInfo.GetStringComparer` return the same answers as the current code on every
  probed pair, so the difference is in the platform's collation weights rather than in a
  missing API. `System.Globalization.Collator` does not exist in .NET. The revisit
  triggers are listed in `MIGRATION_STATUS.md`.
* H2 error codes / catalogue / quoting are all verified differentially; the
  remaining open divergences are listed in `MIGRATION_STATUS.md`.
* Allocation behaviour of the hot string paths is pinned by
  `tests/H2Sharp.Tests/StringUtilsAllocationTests.cs`; the measured before/after
  numbers are in the performance table of `MIGRATION_STATUS.md`.
